## 1. 失败签名机制（FIX_LOG 记录约定）

> 目的：把「同一失败签名第二次出现禁止同方向再试」（根 `AGENTS.md` §4）从**靠回忆**变成**靠一条文本检索判定**。

- **声明（declaration）**：某条记录把一处现象当作一次失败/意外事件登记时，在该行写一个反引号包裹的稳定短标识 `` `[sig:<kebab-case>]` ``。同一签名跨记录**复用同一串**；换新签名才起新串；描述文字自由写，检索只认 slug。
- **引用（reference）**：正文其他地方再提到同一签名时写**裸形式** `sig:<kebab-case>`（无反引号、无方括号），仅作可读关联，不计入记录数。同一事件的追记/续查也只写裸形式——防止把一次事件数成两次。
- **每条记录内同一 slug 只声明一次**；没有失败时写 `- **失败签名**：无（本记录不声明签名）`，不伪造 slug。
- **条目末尾计数字段（必填）**：`- **同签名此前出现次数**：sig:<slug> = <n>`，n = 落笔时本文件其他记录已声明该 slug 的记录条数；多签名用 `；` 分隔；无签名写 `不适用（本记录未声明签名）`；判不了写 `未知（证据不足）`，不留空也不猜 0。
- **检索复核命令**：Git Bash `grep -c "\[sig:<slug>\]" FIX_LOG.md`；PowerShell `(Select-String -Path FIX_LOG.md -Pattern '\[sig:<slug>\]').Count`。
- **评审落点**：同一 slug 命中 ≥2 条记录 ⇒ 判「**重复**」；记录都带签名字段且除本条目外检索为 0 ⇒ 判「**干净窗口**」；字段缺失、slug 写法不统一、或声明数与计数对不上 ⇒ 判「**证据不足**」。
- **边界**：FIX_LOG 仍是唯一的失败记录入口，不另建并行日志/台账/索引表；清理动作只走 `scripts/trash` 与 `scripts/safe-clean`。

## 2. TOP 排障路径摘要（GOTCHAS #DP-01~20 提炼）

> 每条按「触发场景 → 判据/正确做法 → 出处」浓缩。完整取证过程见本地 `docs/agents/GOTCHAS.md`。

### 2.1 门禁/CI 类

| 场景 | 判据 / 正确做法 | 出处 |
|---|---|---|
| CodeQL java/kotlin 慢性红灯 | `github/codeql-action/analyze` 不会执行 build-command；init 与 analyze 之间必须有显式构建步骤，且必须 `--no-daemon --no-build-cache --no-configuration-cache --rerun-tasks`（否则 cache 恢复后编译器没跑、tracer 抓不到源码） | #DP-01 |
| 本地 spotlessCheck 报的文件清单与 CI 不同 | 根 `build.gradle.kts` 的 `lineEndings = PLATFORM_NATIVE` 使 Windows 判定与 Linux（LF）不同；本地绿灯 ≠ CI 绿灯。以 CI 日志 ktlint 期望块为准手工对齐；改完自证：去空白 sha256 相同、`+` 行精确命中、CR 字节 0 | #DP-06 |
| 覆盖率门禁红（"被测到却计 0"） | 先按类拆解 jacoco XML 找 covered=0 的类——那是 Robolectric 绕过 JaCoCo 插桩（SandboxClassLoader），不是缺测试。补 `isIncludeNoLocationClasses = true` + `excludes = listOf("jdk.internal.*")` | #DP-09 |
| CI `Run Lint` 红且报 `Unresolved reference` | 该步骤实际含编译；多为 `git add` 漏了 `src/main/res`（本地读工作树、CI 读已提交内容）。`git add` 按目录级列全（源码 + res + test），提交后 `git show --stat` 核对 | #DP-10 |
| 新增 Gradle 模块缺锁 | LockMode.STRICT 下 `--write-locks` 只写本次任务图解析到的配置。按**四族 × 全变体**补：`:<module>:test :<module>:jacocoTestReport :<module>:lint :<module>:assembleAndroidTest --write-locks`；**依赖方也要重生成** | #DP-17 |
| `docs/ci/branch-protection.json` 与 live 漂移 | 分支保护是「单一来源 JSON → apply 写回远端」单向流；任何远端改动必须同轮回填 JSON 并更新 `_measured_at`。真值以 `gh api repos/<owner>/<repo>/branches/main/protection` 为准 | #DP-20 |

### 2.2 本地 Gradle/环境类

| 场景 | 判据 / 正确做法 | 出处 |
|---|---|---|
| Robolectric 下载锁 / 目录锁假红 | 报错 `<failure message="...lock file...">` / `Unable to delete directory ... a process has files open` 即环境问题非代码问题。**完整规避：`--no-daemon --max-workers=1`**（二者缺一不可）；目录锁则 `./gradlew --stop` + 删对应 intermediates 目录 | #DP-07 / #DP-13 |
| 本地全量单测红、报 `transforms/*/metadata.bin` | 并发 Gradle 进程污染 `~/.gradle/caches/<ver>/transforms/`（纯本地环境问题，CI 不受影响）。`./gradlew --stop` + **整个** transforms 目录删除 + `test --no-configuration-cache` 重跑 | #DP-18 |
| 整模块 `:core:ui:testDebugUnitTest` 顺带重写 Paparazzi golden | 普通 test 任务也会录制。验证单个类一律加 `--tests "*XxxTest*"`；整模块跑前跑后对账 `git status --porcelain -- core/ui/src/test/snapshots`；golden 增删不顺手带进无关提交 | #DP-08 |
| 库模块任务名不存在 | flavor 只定义在 `:app`；`feature/*/`、`core/*/` 单变体测试任务名为 `testDebugUnitTest`（非 testDevDebugUnitTest）。确认：`./gradlew :模块:tasks --all` | #DP-03 |
| 本地跑聚合覆盖率任务随机变体假红 | 聚合 `jacocoTestReport` 并行拉起全变体测试，多 JVM 争抢 Robolectric 全局下载锁。只验证 CI 用的 `:app:testDevDebugUnitTest`；或 `--no-daemon --max-workers=1` | #DP-13 |

### 2.3 测试/取证类

| 场景 | 判据 / 正确做法 | 出处 |
|---|---|---|
| 仪器化用例红绿漂移（键盘类） | 单次 `sleep` + dumpsys 快照证不了「从不」；判屏幕状态要**全程周期采样**。Compose Dialog/Sheet 是独立窗口，按 `dialog|sheet|popup` 关键字过滤恒为 0 是假阴性。**定机制用「只翻一个设备状态」的 A/B**（如 `ime disable` 全关后再跑），别用相关性猜机制；红率不能当基线 | #DP-05 |
| 模拟器启动后消失 | Bash 工具命令 shell 退出会带走 `&` 后台子进程；启动模拟器用 `run_in_background: true` 托管 | #DP-07 |
| 设备路径被 Git Bash 改写 | `adb shell` 设备路径命令前加 `export MSYS_NO_PATHCONV=1`；但 `adb pull` 本地目标要写 `C:/...` 形式 | #DP-07 |
| 单测里 `TestScope.backgroundScope` 协程不执行 | `advanceUntilIdle()` 驱动不了 backgroundScope。用共享同一 `testScheduler` 的独立 scope：`CoroutineScope(UnconfinedTestDispatcher(testScheduler))`，配 `clock = { testScheduler.currentTime }`；结束后 cancel | #DP-19 |

### 2.4 代码/工程类

| 场景 | 判据 / 正确做法 | 出处 |
|---|---|---|
| 子页面顶栏压住第一行 | `BrandTopBar` 与内容 `Column(fillMaxSize())` 写成同级兄弟，在 NavHost 的 Box 里重叠。正确：外层再套一层 `Column(fillMaxSize + pageBackground)`。新建子页面先看同模块已有结构 | #DP-14 |
| 行区间切片搬代码括号失配 | 每块算 `t.count('{') - t.count('}')` 必须为 0；删区间从大行号往小行号删；替换写成带断言次数的 `sub(old, new, n, label)`，`write_text` 放所有断言之后；复制整块 import 会带进目标模块没有的依赖，用 ktlint -F 剪（语法错误时 -F 不动作） | #DP-12 |
| 正则批量改 strings 静默失败 | 改词条值优先 `str.replace(old, new)`；替换后立即断言新值在文本里（`assert new_value in t`）；批量文本处理写成脚本文件跑，别嵌在 `-c` 里叠三层引号 | #DP-16 |
| locale 缺口成片 | 开工先跑 parity 门禁预判；往模块加词条几乎必然要连带补 zh-rTW；按用词习惯手写繁体；顺手归一 CRLF→LF | #DP-11 |
| 工作树被批量删除（29 个跟踪文件） | 先别慌、别 `git add -A`：`git status --short | grep "^ D"` 列清单，`git checkout -- $(git status --short | grep "^ D" | awk '{print $2}')` 从 HEAD 恢复；先查 `git stash list` 与 `.trash/`；**未提交改动 + 被外部硬删 = 不可恢复**，重要改动尽早提交 | #DP-15 |
| 同一工作区多会话并发 | 别人的提交会落在你刚建的分支上、`git status` 突然变干净。先 `git reflog -12` + `git branch -vv` + `git show --stat <sha>` 判性，**不要** reset/branch -D/clean -fd；收拢范围靠显式 `git add -- <路径>`；不替对方 rebase/cherry-pick | #DP-04 |
